## 第一批：修正导航与状态

### UX-01 / P0：赛事详情的收藏入口未进入收藏

证据：运行复现，当前源码仍存在对应缺口。

复现：首页打开赛事，点击赛事详情底部星形收藏入口，回到首页后仍显示赛事列表；再点击首页收藏才进入收藏页。

源码：`EventDetailActivity.setupBottomNavigation()` 使用 `CLEAR_TOP | SINGLE_TOP` 并传入 `tab=favorites`。`MainActivity` 仅在 `onCreate()` 读取该参数，没有 `onNewIntent()`；基类也没有实现该处理。

修改：统一处理初始 Intent 与新 Intent，更新 Activity 的 intent，并同步内容、筛选区和底部导航选中状态。

验收：已有首页实例、从赛事进入收藏时，一次点击即可显示收藏；返回赛事也能正确切换。分别测试已有 Activity 与新建 Activity 的入口。

### UX-02 / P1：收藏为空时整页留白

证据：运行复现；当前首页布局及观察逻辑未处理空内容界面。

修改：区分首次无收藏、筛选后无结果、加载中、加载失败。无收藏显示说明和“浏览赛事”；筛选无结果提供“清除筛选”；失败保留内容并提供重试。

验收：上述状态各有对应文案和动作，加载中不闪现无收藏提示；有内容时空态完全隐藏。

### UX-03 / P1：未搜索就显示“没有找到匹配的卡牌”

证据：运行复现，搜索框为空时同时出现搜索历史标题与无结果提示。

源码：`SearchActivity.observeViewModel()` 仅依据结果列表是否为空显示 `textViewEmpty`；`SearchViewModel` 初始结果为空，未将初始、加载、成功空结果、失败合并为互斥状态。

修改：建立互斥的搜索界面状态。首次进入显示输入提示/历史；请求中显示进度；成功且为空才显示无结果；失败展示可重试错误。历史为空时隐藏无意义的“清空”动作。

验收：首次进入、清空输入、加载、成功空结果、网络失败各只显示对应内容；错误不能最终退化为“没有匹配卡牌”。

### UX-04 / P1：刷新反馈与实际行为不一致

证据：源码确认，未在运行中验证失败场景。

源码：`MainActivity.onOptionsItemSelected()` 调用异步 `loadEvents()` / `loadFavoriteDecklists()` 后立即提示“已刷新”。`loadEvents()` 读取 repository 的赛事列表，并非该菜单直接发起赛事抓取。

修改：先明确本地重新读取与获取最新赛事的产品含义；“已刷新”只在操作成功完成后出现。失败提供重试，已有内容继续可见。

验收：请求/读取未结束时不提示成功，失败不提示成功；用户能区分本地内容刷新与获取远程最新赛事。

## 第二批：提高阅读效率与一致性

### UX-05 / P1：首屏内容占比偏低

证据：运行观察；首页独立下载区域较高，套牌顶部赛事信息、空标签/备注区和较高卡牌行压缩了首屏牌表空间。

修改：首页将获取赛事动作收敛为紧凑入口；套牌信息压缩成摘要，标签备注为空时提供紧凑编辑入口；单卡采用数量—牌名—费用对齐的行式布局，保留充分触控面积；主牌/备牌标题中文化。

验收：在同一模拟器、字体与套牌下对比首屏可见单卡行数，目标至少增加 2 行；长中文牌名与双面牌名称仍可完整理解；卡牌操作区域不因压缩而难以点击。

### UX-06 / P1：中文界面夹杂内部状态及英文标签

证据：运行可见 `8 Decks`、`Loaded 8 decklists`、`Format`、`Date`、`Player`、`Mainboard`。当前代码仍有对应字符串。

修改：统一为“8 套牌”“已加载 8 套牌”“赛制”“日期”“牌手”“主牌/备牌”。区分下载、更新和已缓存状态，再决定“下载所有套牌”的文案，避免仅凭套牌数量判断卡牌内容已完整缓存。底部两个入口始终显示文字；隐藏筛选器时连同相邻多余分隔线一起处理。

验收：中文模式下系统状态和操作名称一致；赛事原始名称与牌手名可保留原文；两个导航入口均可直接辨认。

### UX-07 / P1：单卡弹窗的信息缺失需要明确反馈

证据：旧版运行中“不毛高地”弹窗展示英文卡图、类别和稀有度，但未显示规则文字；不能据此认定当前源码或服务端必然缺失该数据。

修改前检查：核对本地 CardInfo、服务端返回值及弹窗字段映射，分别检查规则文字为空、加载失败、中文翻译缺失的情况。保留已有单卡预览和版本选择能力。

目标：可用规则文字正常显示；中文缺失时回退英文；真正缺失时说明并允许重试。后续再加入同套牌上一张/下一张切换。

验收：有规则文字的单面牌、双面牌、无费用土地分别检查；关闭弹窗后维持套牌位置。不能把土地无费用当成费用缺失。

## 第三批：需专项验证后再改

### UX-08 / P2：列表滚动与状态恢复

证据：源码风险，尚未通过长列表或旋转实测确认故障。

首页使用 `NestedScrollView` 包裹 `wrap_content` 的 RecyclerView；切换底部页签重新设置 adapter；筛选状态是 ViewModel 中的内存状态。套牌列表用 LinearLayout 动态创建单卡视图。

验证：准备大量赛事数据，测量滚动卡顿；在较深位置切换收藏后返回；进入单卡并返回；旋转屏幕与进程重建后检查选中页签、筛选、折叠区和滚动位置。

修改条件：根据实测改成单一滚动列表，并为各页签独立保存布局状态；必要时使用 SavedStateHandle 保存页面状态。不要把未经测量的风险写成已发生的卡顿。

### UX-09 / P2：搜索请求顺序与筛选摘要

证据：源码风险，尚未通过网络请求实测。

`SearchViewModel.search()` 每次独立启动协程，未见取消旧请求或结果序号保护；慢的旧请求可能覆盖新的关键词结果。

验收：使用可控延迟构造先搜 A、后搜 B、A 最晚返回的情况，最终只显示 B 的结果。高级筛选激活时显示摘要和清除入口，返回搜索页仍能理解当前条件。
